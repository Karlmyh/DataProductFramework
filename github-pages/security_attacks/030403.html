多体关系核验
攻击页面

判断多个独立业务对象之间是否存在所有、任职、授权、控制、交易或绑定关系。

攻击面判定

核心交付

判断多个独立业务对象之间是否存在所有、任职、授权、控制、交易或绑定关系。

主要暴露

单次关系判断可被组合成组织、交易、设备或社会网络。

分类边界

对象具有独立业务角色；返回开放关系对象或路径时归入 030103。

四级产品分支

  1. 权威登记关系核验
  2. 合同、证照与授权关系核验
  3. 账户、设备、交易与行为关系核验
  4. 多源关联与关系推定核验

主要攻击

  1. 01关系枚举（有条件成立）
  2. 02账户与设备绑定探测
  3. 03控制关系图重建
  4. 04多源关联推断

账户归属核验如何形成攻击

攻击者已知

分别掌握企业标识候选集和账户标识候选集，但不知道企业与账户之间的对应关系。

攻击者操作

把两组候选任意配对并重复查询，利用稳定的“是／否”响应筛出成立的组合。

攻击所得

将单次核验结果拼成原本未公开的企业—账户映射，进一步重建控制或交易关系。

适用边界：接口必须允许任意配对试探，且缺少授权校验、严格限频或异常检测。若每次核验都要求证明对企业或账户一方的控制权，这种关系枚举攻击就不成立。
