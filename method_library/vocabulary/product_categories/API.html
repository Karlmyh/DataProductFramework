额外检索线索

  • 2019 ML-Leaks: Model and Data Independent Membership Inference Attacks and Defenses on Machine Learning Models (NDSS)
  • 把 API 场景下的成员推断从早期高假设设置推进到更弱先验、更少 shadow 假设的黑盒攻击，是这一类 API 产品的关键扩展文献。
  • 2021 Systematic Evaluation of Privacy Risks of Machine Learning Models (USENIX Security)
  • 这篇工作不只是攻击，也重新定义了 API 场景下该怎么评估成员推断风险，非常适合作为规则页里 R / R0 / R_full 进一步抽取的参考。
  • 2023 SoK: Membership Inference is Harder Than Previously Thought (PoPETs)
  • 对 API 型黑盒目标做了系统复盘，提醒不能把所有 label/score 接口都默认当成高风险，也适合放进 contested / realistic threat discussion。
  • 2025 Comparing Different Membership Inference Attacks With a Comprehensive Benchmark (IEEE TIFS)
  • 用 MIBench 系统比较 15 种 MIA，对 API 类目标尤其重要，因为它直接触及“哪些攻击真的稳定、哪些只是评测偶然”的问题。
  • 2024 You Only Query Once: An Efficient Label-Only Membership Inference Attack (ICLR)
  • 这篇工作把 label-only API 场景下的查询预算从上千次压到一次，是 API + label_output 组合非常关键的工程化推进。
  • 2024 OSLO: One-Shot Label-Only Membership Inference Attacks (NeurIPS)
  • 进一步把 one-shot label-only MIA 做成高精度攻击，说明对 API 来说，“只返回 hard label”已经不足以作为低风险假设。

survey 引文滚雪球

  • 对 API 这个类别，最值得继续沿 survey 链往下追的是：
  • Shokri 2017 -> ML-Leaks 2019 -> Systematic Evaluation 2021 -> MIBench 2025
  • Shokri 2017 -> Label-Only MIA 2021 -> Sampling Attacks 2021 -> Limited Query MIA 2022 -> YOQO 2024 -> OSLO 2024
  • 这两条链正好对应：
  • score_or_logit API
  • label_output / binary_decision API
  • 所以下一轮如果继续补 API 类，不应该泛搜 ML privacy，而应该沿这两条链补。
